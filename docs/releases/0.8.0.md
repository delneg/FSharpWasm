# NetWasm 0.8.0: C# just beat Rust at Wasm size

NetWasm 0.8.0 is available on NuGet.org.

**47,798 bytes with precise garbage collection. Rust's size-oriented profile:
53,635 bytes.** For the same print-`42` workload, NetWasm's measured 0.8.0
release is **10.9% smaller**. Both outputs are WASI Preview 2 components;
the Rust reference uses Rust 1.95.0 with `opt-level = "z"`, LTO, one codegen
unit, aborting panics and stripped symbols. NetWasm uses Release/Oz with its
default Compact collector. This is a workload/profile comparison, not a
language-wide size guarantee.

See [the measurements and reproduction settings](../size-and-methodology.md).
The complete component is **13,501 bytes with Brotli quality 11**.
These figures were reproduced using the released SDK and template packages.

NetWasm 0.8.0 focuses on smaller applications, faster execution, and closer .NET
behavior. It introduces NetWasmGC, adds a non-collecting allocator for bounded
workloads, improves generated WebAssembly, and substantially updates CoreLib.

## Garbage collection and allocation

- Added **NetWasmGC**, an independent precise, non-moving mark-and-sweep collector
  designed for throughput. Select it with `NetWasmGarbageCollector=NetWasm`.
- NetWasmGC uses size-class blocks, batched zeroed allocation runs, bitmap tracing
  and sweeping, and an indexed ownership lookup. It supports NetWasm's managed
  lifetime features, including finalizers, weak references, ephemerons and
  interior references. This release uses a non-generational collector.
- Added **Bump**, a non-collecting allocator for short-lived applications with
  bounded memory consumption. Select it with `NetWasmGarbageCollector=Bump`.
  Memory is retained for the application's lifetime. Applications requiring
  finalization, weak handles or ephemeron handles are rejected at build time.
- Compact remains the default collector for small output. Boehm remains
  available. Collector selection is an application setting; libraries remain
  collector-neutral. Runtime packages support both wasm32 and wasm64.
- Reduced precise-root overhead using contiguous root-slot storage, cached
  reference reads, and elimination of proven redundant root writes and clears.
- Reduced allocation overhead and duplicate clearing while preserving managed
  zero-initialization guarantees. Runtime frame storage is reused more efficiently.
- Made finalization support conditional on application requirements so unused
  machinery can be omitted from the final module.

## Generated-code performance and size

- Improved specialization of closed generic calls and default comparers,
  reducing virtual dispatch and unnecessary value copies.
- Added managed inlining for supported small methods, field accessors and
  aggregate-forwarding wrappers at `O3`.
- Improved value-type handling, including selected address-taken values,
  transient `DivRem` results, small copies and aggregate value storage.
- Improved hot array loops with cached array metadata, proven bounds-check
  elimination and bounded loop unrolling at `O3`.
- Added loop-invariant field hoisting and elimination of temporary views over
  static data under the applicable optimization presets.
- Improved dense control-flow dispatch with branch tables, direct transitions
  and preservation of structured loops.
- Reduced unnecessary boxing used only for null comparisons, folded closed-type
  conditions, and propagated constant arguments before retaining reachable code.
- Lowered supported integer bit operations and floating-point `CopySign` to
  native WebAssembly instructions. Added direct lowering for supported memory
  bulk operations and ordinal string equality.
- Added speed-oriented native runtime assets selected automatically for `O1`,
  `O2` and `O3`; size-oriented builds retain the smaller runtime profile.
  Optimization choices continue to distinguish speed from output size.

## CoreLib performance and compatibility

### Collections

- Updated major collection implementations against .NET 11 sources, including
  dictionaries, hash sets, lists, queues, stacks, sorted collections, priority
  queues, ordered dictionaries and non-generic collections.
- Improved default-comparer specialization, dictionary lookup/insertion paths,
  string-key hashing and collision handling, and dedicated HashSet storage.
- Updated array sorting, bucketed ArrayPool behavior, immutable/frozen collection
  foundations, read-only wrappers and collection enumeration contracts.
- Improved ConditionalWeakTable and dependent-handle behavior.

### Numerics, text and formatting

- Reworked decimal arithmetic around upstream addition, subtraction,
  multiplication, division and rounding algorithms, with reduced copying.
- Fixed numeric conversion, parsing and rounding edge cases, including negative-
  scale decimal division, zero-remainder BigInteger division, narrow-integer bit
  operations and Guid big-endian construction.
- Reduced temporary allocations in numeric span parsing and formatting,
  BigInteger byte writing and modular exponentiation.
- Improved StringBuilder growth, ordinal comparisons, invariant ASCII casing,
  string construction from spans, trimming and empty-array reuse.
- Added scalar SearchValues strategies and multi-string search using Aho-Corasick.
- Improved invariant Unicode data, numeric formats, format-provider handling,
  overlap-safe span copying and buffer operations.
- Improved runtime-entropy seeding for Random, HashCode and randomized hashing.

### Async, I/O, dates and other runtime contracts

- Improved Task and ValueTask behavior, cancellation timer ownership, late
  continuations, WhenAny cleanup, WhenEach, async-local state and PeriodicTimer.
  Reduced allocations through lazy task promises and reusable typed continuations.
- Improved stream async behavior, buffered and memory streams, async disposal,
  text-writer format providers and Console output semantics.
- Improved deterministic Path operations. This does not add unrestricted host
  filesystem access.
- Expanded invariant date/time formatting and parsing, corrected ambiguous-local
  DateTime handling and file-time behavior, and improved timezone transition
  lookup and adjustment-rule projection.
- Updated Uri parsing, resolution, escaping, IDN/IRI handling and WebUtility
  behavior, plus string-based credential lookup contracts.
- Improved multicast-delegate behavior, cloning and invocation-list enumeration;
  improved exception state, HResults, argument validation, tuples, portable
  diagnostics metadata and selected cryptographic random APIs.

## Expression trees

- Expanded the bounded interpreter profile to admit enums and selected nullable
  values in supported expression positions.
- Added supported primitive/nullable equality, reference identity, selected
  string equality and explicitly supplied executable equality methods.
- Improved method-call forwarding and execution-profile validation.
- `Compile()` continues to use the interpreter. This does not add runtime code
  generation or general reflection. Enum equality, arbitrary struct execution
  and other excluded shapes remain unsupported.

## Correctness and SDK fixes

- Fixed managed entry-point argument projection. `dotnet run -- ...` and
  configured arguments reach `Main(string[] args)` without losing the first
  argument; `Environment.GetCommandLineArgs()` retains the program-name entry.
- Fixed GC rooting of captured stack storage across allocation safepoints.
- Fixed control-flow and inlining cases involving terminal exits, branch joins,
  exception continuations and caller continuation regions.
- Corrected type-initialization triggers, closed generic constrained dispatch
  and async wrapper runtime-import selection.
- Updated the Wasmtime toolchain pin to 49.0.3.

## Compatibility notes

- Caller-supplied runtime-file overrides through `NetWasmRuntimeModulePath` or
  added `NetWasmComponentRuntime` items are now rejected. To test a modified
  runtime, use a uniquely versioned Runtime.Pack package through a local feed.
- The runtime remains single-reactor and reflection-free. These CoreLib updates
  do not imply desktop-wide .NET API, culture, threading or expression-tree parity.
- DateOnly and TimeOnly general parsing use the documented invariant grammar.
  Use `ParseExact` or `TryParseExact` for an explicitly specified input format.
