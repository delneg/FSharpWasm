# NetWasm 0.10.0: GC revamp

NetWasm 0.10.0 is available on NuGet.org.

This release rebuilds NetWasm's garbage collectors. Objects no longer carry a
collector header, an array is a single allocation, NetWasmGC allocates by
advancing a pointer, and Compact has a new core built for size and memory. On
our allocation benchmarks NetWasmGC now takes 26 to 40% less time than Mono
AOT, and less time than desktop .NET 11's JIT on two of the three workloads.
Both collectors use far less memory. The Boehm collector is removed.
Applications that ship time zone data start in a fraction of the time.

## Garbage collection

- Collected objects carry no collector header. Every collector reads an
  object's size and references from its type. NetWasmGC no longer adds 32
  bytes to every object on wasm32, and Compact's header is one word.
- An array is one allocation: its fields, then its elements. Rectangular arrays
  keep their shape inline.
- NetWasmGC allocates by advancing a pointer through a run of zeroed slots,
  keeps its mark state in bitmaps beside each block, and never traces objects
  that hold no references, such as strings.
- Compact has a new mark-sweep core, built for size first and memory second:
  a one-word header, 64 KiB chunks, free lists by size, and a mark stack that
  falls back to rescanning the heap when it cannot grow. It replaces the
  collector derived from AssemblyScript.
- Bump stores arrays inline too.

Median time and peak linear memory at `NetWasmOptimization=O3`, against the
0.9.0 figures from the same host and harness:

| Workload | NetWasmGC 0.9.0 | NetWasmGC 0.10.0 | Compact 0.9.0 | Compact 0.10.0 |
| --- | ---: | ---: | ---: | ---: |
| Full transaction | 50.4 ms, 36.9 MiB | 43.9 ms, 20.9 MiB | 75.1 ms, 32.8 MiB | 59.1 ms, 17.4 MiB |
| Retained object graph | 13.3 ms, 31.7 MiB | 8.8 ms, 15.7 MiB | 27.7 ms, 26.7 MiB | 17.8 ms, 11.9 MiB |
| UI churn | 22.0 ms, 7.3 MiB | 17.6 ms, 7.3 MiB | 44.2 ms, 2.9 MiB | 32.9 ms, 1.7 MiB |

The print-`42` component published at `Oz` is 47,895 bytes with Compact
(47,798 in 0.9.0), 50,855 with NetWasmGC (51,300) and 43,864 with Bump
(43,794). See [Performance](../performance.md) and
[Choosing a garbage collector](../runtime-garbage-collection.md) for the
method, Mono AOT and desktop figures.

## Performance

- Storing a reference into an array skips the covariant type check when the
  array's element type is known exactly: the array was created by `new T[n]`,
  or its element type is a sealed class such as `string`. This applies at `O1`,
  `O2`, `O3`, `Os` and `Oz`.

## Time zones

- With `NetWasmTimeZoneMode=Full`, an application in `Australia/Melbourne`
  starts in 0.29 s instead of 8.4 s in Firefox, 0.11 s instead of 1.1 s in
  Chromium, and 0.12 s instead of 1.26 s in WebKit. Start-up reads only the
  zone index and the selected zone. Other zones are read when
  `FindSystemTimeZoneById` or `GetSystemTimeZones` first needs them, and
  invalid data there throws `InvalidTimeZoneException`.
- The guest no longer hashes the time zone file. Browser hosts and the local
  launcher check its SHA-256 digest against the deployment manifest before
  mounting it. See [Time zone assets](../timezone-assets.md).

## Fixes

- A writable reference to an element of a reference-type array, as in
  `Volatile.Write(ref names[i], value)` or `ref object item = ref items[i]`,
  could fail to compile with NW1008. It now compiles, and throws
  `ArrayTypeMismatchException` on a covariant array as .NET does.
- Calling `ToString()` directly on a struct that does not override it returned
  the name of an unrelated type. It now returns the struct's type name, as a
  boxed call does.

## Validation

- The full compiler test suite passes with Compact, the default collector. Its
  collector-heavy cases also pass with NetWasmGC. With Bump, every such case
  passes except those that need finalization, weak references or a real
  collection, which Bump does not provide.
- Page modules, worker modules, WIT workers, commands, time zone applications
  and the #89 reproductions pass in Chromium, Firefox and WebKit, in Debug and
  Release, published on Linux, macOS and Windows hosts from the release
  candidate packages.
- Every benchmark run's result matches the same program on desktop .NET 11.

## Upgrading

- The Boehm collector is removed. A project that sets
  `<NetWasmGarbageCollector>Boehm</NetWasmGarbageCollector>` fails the build
  with NWPACK007. Remove the property to use Compact, the default, or set
  `NetWasm` for throughput.
- A custom host that mounts time zone data from the standalone generator
  should verify the payload before mounting it, because the guest now trusts
  the mounted file.
